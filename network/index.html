The network

This site is one of several under sgit.ai. The boundaries matter, because the fastest way to make a network of sites useless is to have three of them half-cover the same subject. What follows is who owns what, and where this site defers.

Four siblings mention Wardley zero times

Which is worth saying rather than quietly linking around, because in at least one case it is a hole with a specific shape.

  • nhi.sgit.ai — the strongest candidate. graphs.sgit.ai records four unrendered permissions maps from that work, including one called "Hope Driven Development" — and nhi.sgit.ai/hope/ contains no maps at all. Its five-step framework is Enumerate, Map, Bound, Observe, Issue no credential. It is asking for one. Find them, render them, ship them: T5.
  • sg-sentinel.sgit.ai — zero mentions across 23 documents. Allowlist-versus-denylist is a natural map, and the evolution axis is the right tool for arguing about which one a control should be.
  • riskmandate.ai — zero mentions. RAMM maturity is adjacent to doctrine, and the evolution-versus-maturity rule is directly about the difference between them.
  • sgit.ai — has the maps and the vault, and its network page lists four sites and no mapping site. It needs a fifth entry, which is N3.

Vault key discipline, since this page links to vaults. Every key on the sgit.ai catalogue is an sgit_rk1_ read key, published on purpose. No write keys are exposed anywhere. Before linking any vault, confirm its write key is escrowed — publishing a read key for a vault whose write key is lost freezes it permanently. The release gate refuses to publish anything shaped like a vault key at all.
