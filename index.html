Wardley Mapping · doctrine · maps for agents

Maps are claims,
not pictures

A Wardley map asserts where every component sits on the evolution axis. That makes it arguable — and almost nobody publishes theirs anywhere it can be argued with. This site publishes its maps as source next to the render, its doctrine ratings with the artefact each one rests on, and its resource list with the date every link was last checked. Everything here is meant to be disagreed with in a pull request.

Four claims about the method, and what would falsify each

These are the opinionated part. Each one comes out of applying mapping to an agentic software project for six months, each states what evidence would change it, and each is somewhere the standard doctrine gets pushed or contradicted.

The claimWhy it matters
De-commoditisationA thing can be commoditised at one phase of evolution while still being meaningfully custom-built at the next. The map shows the commodity; it does not show the shield.
The custom-axis verdictYou can relabel the evolution axis — air gap → file → API → event-driven — but only sometimes. Relabel the axis when the thing genuinely evolves; use a maturity model when the thing merely improves.
You cannot map a gapA gap has no evolution, so it cannot be positioned. What you get instead is a map shape: the ends are solved, the middle is people.
Maps are graphs with positionA map is not a separate artefact from the graph — it is a projection of one. Map queries are graph queries with positional filters. And it has no implementation, which the page says.
Anybody who spends a lot of money on tokens has an engineering problem. They are using explorer-type code and solutions in a commodity environment.

4 June 2026, and unpublished until now. It is the sharpest thing in the corpus because it turns a strategy framework into an operational cost diagnostic: an invoice becomes evidence of a position on the evolution axis. If you are an agent

/llms.txt and /llms-full.txt are the whole surface, /agents/concepts.json is the definitions endpoint, and /agents/ carries the two things that are easy to get wrong and expensive to get wrong. First: Mermaid and OnlineWardleyMaps coordinates are [visibility, evolution], not [x, y] — transposing them renders without an error and asserts something else entirely. That is proven here by rendering, not repeated from documentation. Second, and it is not a footnote: the evolution axis plausibly encodes consensus rather than objective fact, so a model placing components on it is generating consensus-shaped output with no underlying evidence. An agent must surface its placements as contestable claims requiring challenge, never as findings.
